# DeepDive 03 - 타입 힌트 적용 영향 분석

## 과제2에서 발췌한 타입 힌트 분류
1. **기본 컬렉션**: `list[Task]`
2. **경로/입출력 경계**: `Path`, `Iterable[str]`
3. **제너레이터 시그니처**: `Generator[str, None, None]`
4. **반환 타입 명시**: `-> None`, `-> list[Task]`

## 디버깅/유지보수 영향
- 함수 계약이 문서 역할을 하여 변경 영향 추적이 쉬워짐
- 리뷰어가 런타임 전에 타입 불일치를 예측 가능
- 리팩토링 시 호출부 자동 추적(IDE) 정확도 개선

## 타입 힌트 한계
- 런타임 강제가 없어, 외부 입력은 별도 검증 필요
- Any 남용 시 사실상 타입 안정성 상실
- 복잡 타입 체계는 팀 내 학습 비용을 유발

## boilerplate 프로젝트 안내
`boilerplate/`는 대규모 협업을 가정한 최소 구조로, 타입 힌트가 주는 이점과 한계를 코드 레벨에서 관찰할 수 있도록 구성했다.
