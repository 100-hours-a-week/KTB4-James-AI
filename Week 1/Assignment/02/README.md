# Assignment 02 - 패키지 구조 리팩토링

## 리팩토링 철학
- **단일 파일 -> 모듈 분리**: 모델/입출력/실행 로직을 분리해 변경 영향도를 축소
- **설치형 배포**: `pyproject.toml` + console script로 실행 표준화
- **타입 힌트 적용**: 함수 경계의 입출력 계약을 명시해 협업 디버깅 비용 감소
- **지연 처리 도입**: 파일 파싱 시 generator 사용으로 대용량 입력 대비

## 타입 힌트가 협업에 주는 이점
- IDE 자동완성 개선
- 코드리뷰 시 인터페이스 의도 파악 용이
- 정적 분석(mypy/pyright)과 결합 시 런타임 버그 조기 발견

## 타입 힌트의 한계(동적 타이핑 맥락)
- 런타임 강제가 아님(annotated라도 잘못된 타입이 들어올 수 있음)
- 외부 라이브러리 stub 품질 의존
- 과도한 제네릭/복잡한 타입은 가독성 저하 유발

## 이터레이터/제너레이터 도입 포인트
- `iter_lines(path)`는 한 줄씩 `yield`하여 메모리 상주량을 줄임
- 로그/대용량 텍스트 처리 시 list 일괄 로딩 대비 유리
