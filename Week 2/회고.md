이번 주 작업에서는 과제의 난이도가 이전보다 높아졌음을 체감했다. 단순히 기능 하나를 구현하는 수준이 아니라, 하위 과제가 여러 개 존재했고 각 단계별 수행 과정도 세분화되어 있어 초기 프롬프트를 작성하는 과정에서 수정이 반복적으로 필요했다. 특히 AI 모델 서빙은 직접 구현해본 경험이 없는 분야였기 때문에, 우선 웹에서 소규모로 구현된 예제 코드들을 찾아보며 전체 구조를 이해하는 과정이 선행되어야 했다. 이후 이를 바탕으로 프롬프트에 세부 지침을 추가하며 작업을 구체화해 나갔다.

이번 작업에서는 Codex 모델 또한 요청의 규모가 크고 세부 지침이 충분하지 않다는 점을 어느 정도 인지하고 있는 모습이 보였다. 실제로 첫 번째 결과물은 요구된 작업 범위에 비해 상당히 빈약했고, 핵심 기능과 설명이 다수 누락된 상태였다. 그 결과 Week 1보다 훨씬 더 세세하게 코드와 README 파일 내용을 검토해야 했으며, 부족한 부분은 여러 차례 수정 요청을 반복해야만 원하는 수준으로 보완할 수 있었다.

이 과정을 통해 흥미로운 점도 확인할 수 있었다. 경험이 부족한 분야일수록 생성형 AI에게 추상적인 형태로 작업을 지시하게 되는데, 오히려 이런 경우에는 요청 규모가 크더라도 결과물의 밀도와 완성도가 낮게 생성되는 경향이 있었다. 반대로, 이미 어느 정도 경험이 있는 분야에서는 핵심 요구사항만 간결하게 정리해도 결과물이 더 구조적이고 완성도 높게 생성되었다. 즉, 생성형 AI를 효과적으로 활용하기 위해서는 사용자의 도메인 이해도와 구체적인 지시 능력이 매우 중요하다는 점을 체감했다.

앞으로 진행될 과정에서는 지금보다 더 익숙하지 않은 개념과 기술들을 다루게 될 가능성이 높다. 따라서 단순히 생성형 AI에 의존하기보다는, 직접 코드를 작성하고 구조를 이해하는 비중을 늘리는 방향이 더 효율적인 학습 방법이 될 것이라고 생각한다. AI를 보조 도구로 활용하되, 핵심 구현과 이해 과정은 스스로 수행해야 장기적으로 문제 해결 능력과 개발 역량을 함께 키울 수 있을 것이라는 점을 이번 과제를 통해 배울 수 있었다.
